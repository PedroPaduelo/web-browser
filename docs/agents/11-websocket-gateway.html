WebSocket Gateway Agent

Ativo

Gerencia upgrade HTTP→WS e routing de conexões WebSocket

Configuração

Parâmetro Valor Descrição
noServer true Modo manual de upgrade HTTP→WS
perMessageDeflate false Compressão de mensagens desabilitada
maxPayload 512KB Tamanho máximo do payload
setNoDelay true Baixa latência (Nagle desabilitado)

Upgrade HTTP→WS

O handler de upgrade (server.on('upgrade')) processa a conexão WebSocket através de uma sequência de validações:

1 Requisição HTTP recebida
↓
2 Extrai token e sessionId dos query params
↓
3 Valida token JWT
↓
4 Verifica session existe e pertence ao tenant
↓
5 Verifica resources existem
↓
✓ Upgrade para WebSocket

Códigos de Erro

  • 401 — Token JWT inválido ou expirado
  • 403 — Session não existe ou não pertence ao tenant
  • 404 — Resources não existem

Rotas WS

Após o upgrade, o routing é feito pelo pathname da URL:

Rota Handler Descrição
/ws/stream streamManager.addClient(ws) Gerencia stream de vídeo/screenshare. Registra em activeWsConnections
/ws/input ws.onmessage Recebe input do cliente, parseia JSON e envia para inputHandler
outros socket.destroy() Conexão rejeitada

Autenticação WS

A autenticação WebSocket é realizada através de query parameters na URL de conexão:

ws://host:port/ws/stream?token=JWT_TOKEN&sessionId=SESSION_ID
  • token: Token JWT válido para autenticação
  • sessionId: ID da sessão do tenant
Nota: O token deve ser validado em cada conexão. Conexões com token expirado ou inválido são rejeitadas durante o handshake de upgrade.

Token Expiry Checker

Um intervalo verifica periodicamente as conexões WebSocket ativas para detectar tokens expirados:

0s
Início do intervalo

setInterval inicia a cada 60 segundos

~1s
Itera activeWsConnections

Para cada conexão, verifica se o token expirou

~2s
Token expirado detectado

Fecha WebSocket com código 4001 e mensagem "Token expired"

60s
Próximo ciclo

Repete o processo

ws.close(4001, "Token expired")

Implementação

O agente é implementado no arquivo index.js e gerencia:

  • Upgrade de conexões HTTP para WebSocket
  • Validação de autenticação (JWT)
  • Validação de sessões e resources
  • Routing de conexões para handlers específicos
  • Monitoramento de expiração de tokens
  • Gerenciamento de conexões ativas
