Visão Geral

Núcleo do Sistema Serende
Descrição

O Session Manager Agent é o agente central do sistema Serende. Ele gerencia o ciclo de vida completo das sessões de navegador remoto: desde a criação inicial até a finalização e cleanup. É responsável pela alocação de displays virtuais, spawn dos processos (Xvfb, Chrome, FFmpeg), monitoramento de timeout e coordenação de todos os recursos.

function allocateDisplay() { for (let d = DISPLAY_MIN; d <= DISPLAY_MAX; d++) { if (!this.displayPool[d]) { this.displayPool[d] = { sessionId: null, allocatedAt: Date.now() }; return d; } } throw new Error('No displays available - pool exhausted'); }

Timeout Tracker

Monitoramento de Inatividade
Mecanismo de Timeout

Cada sessão possui um startTimeoutTracker() que roda em intervalo fixo (ex: 1min) verificando lastActivity. Quando o tempo desde a última atividade excede SESSION_TIMEOUT_MS, a sessão é automaticamente encerrada.

Fluxo Passo a Passo

async stopSession(sessionId, reason = 'user_request') { const session = this.sessions[sessionId]; if (!session) return false; console.log(`[SessionManager] Stopping ${sessionId}: ${reason}`); // 1. Marca status como STOPPING session.status = 'STOPPING'; // 2. Para FFmpeg (graceful SIGTERM) if (session.ffmpeg && !session.ffmpeg.killed) { await this.safeKill(session.ffmpeg, 'SIGTERM', 2000); } // 3. Para Chrome (graceful SIGTERM) if (session.chrome && !session.chrome.killed) { await this.safeKill(session.chrome, 'SIGTERM', 2000); } // 4. KILL Xvfb (sempre SIGKILL - não responde a SIGTERM) if (session.xvfb && !session.xvfb.killed) { session.xvfb.kill('SIGKILL'); } // 5. Merge Chrome profile (opcional - persistência) // Se houver opção de persistência, copia profile para storage // 6. Remove da memória delete this.sessions[sessionId]; // 7. Libera display (com cooldown de 2s) this.releaseDisplay(session.display); // 8. Cleanup de diretórios (async, não bloca) this.cleanupSessionDir(sessionId).catch(console.error); return true; }

stopAllSessions() — GLOBAL

Função de emergência/sistema. Encerra todas as sessões ativas em qualquer tenant. Usada em shutdown, restart de deploy ou recovery de disaster.

async stopAllSessions() { const sessions = Object.values(this.sessions); const results = []; console.log(`[SessionManager] STOP ALL: ${sessions.length} sessions`); for (const session of sessions) { try { await this.stopSession(session.sessionId, 'system_shutdown'); results.push(true); } catch (err) { console.error(`Failed to stop ${session.sessionId}:`, err); results.push(false); } } return results.length; }
⚠️ ATENÇÃO: Esta função não verifica limites nem pede confirmação. Executa em série para evitar resource starvation em cleanup simultâneo.

safeKill Pattern
async safeKill(process, signal = 'SIGTERM', timeoutMs = 2000) { return new Promise((resolve, reject) => { if (!process || process.killed) return resolve(); process.once('exit', (code) => { if (code === null) process.killed = true; resolve(); }); process.kill(signal); setTimeout(() => { if (!process.killed) { console.warn(`[SessionManager] Force kill ${signal} failed, SIGKILL`); process.kill('SIGKILL'); } }, timeoutMs); }); }
Zombie Detection
// Em stopSession(), após SIGTERM+timeout: const waitForExit = (p, timeout) => new Promise(res => { const start = Date.now(); const check = () => { if (p.killed || Date.now() - start > timeout) { if (!p.killed) console.error(`[ZOMBIE] ${p.pid} still alive`); res(); } else { setTimeout(check, 100); } }; check(); });

Segurança

Isolamento e Permissões
Isolamento por Tenant
  • Cada sessão usa diretório dedicado: session-data/{sessionId}-{tenantId}/
  • Processos rodam como usuário do sistema (não root via --no-sandbox)
  • Display virtual (Xvfb) isolado por sessão — nenhum acesso cruzado
  • Limite máximo de sessões por tenant: MAX_SESSIONS
Chrome Security Hardening
  • --no-sandbox Running como não-root evita escalada via sandbox
  • --disable-dev-shm-usage Evita ataques de symlink em /dev/shm
  • --disable-web-security Desabilitado apenas para automação — não exposto publicamente
  • --remote-debugging-address=0.0.0.0 Por padrão bind apenas localhost (127.0.0.1)
  • --user-data-dir Diretório exclusivo por sessão, sem compartilhamento
CDP Access Control

O WebSocket URL retornado por startSession() usac localhost com porta dedicada. Acesso deve ser validado por:

  • Auth Gateway: Verifica sessionToken válido antes de proxyar ws:// → browser
  • CDP Firewall: Bind do Chrome em 127.0.0.1 apenas, não acessível externamente
  • IP Whitelist: Client WebSocket de origem conhecida (frontend do tenant)

Troubleshooting

Problemas Comuns e Soluções
Checklist de Diagnóstico
  • Sessão não inicia: Verifique getAllSessions() e displayPool. Pool esgotado?
  • CDP connection refused: Chrome travou no spawn. Logs em logs/chrome.log
  • No stream received: FFmpeg não captura display. Xvfb rodando? ps aux | grep Xvfb
  • High latency: MJPEG over pipe é ineficiente. Considerar HLS ou WebRTC
  • Zombie processes: Sessões STOPPED mas processos rodando. getSessionRaw() para debugar
  • Display collision: Dois Xvfb no mesmo display. Limpe locks: /tmp/.X11-unix/X{display}
  • Permission denied: Usuário sem permissão para Xvfb socket. Verificar /tmp/.X11-unix perms
  • Out of memory: Muitas sessões simultâneas. Aumentar swap ou reduzir MAX_SESSIONS
  • Timeout not firing: startTimeoutTracker não chamado. Verificar flush de logs
Debug Commands
# Listar todas as sessões ativas node -e "const m = require('./session-manager.js'); console.log(m.getAllSessions())" # Verificar estado do pool de displays node -e "const m = require('./session-manager'); console.log(m.displayPool)" # Inspecionar sessão específica node -e "const m = require('./session-manager'); console.log(JSON.stringify(m.getSessionRaw('abc123'), null, 2))" # Verificar processos zumbis ps aux | grep -E "Xvfb|chrome|ffmpeg" | grep -v grep # Verificar sockets X11 (display locks) ls -la /tmp/.X11-unix/ | grep -E "X1[0-9][0-9]"

Limitações do Design
  • Pool de displays: Apenas 100 displays (100-199). Limitante hardcoded.
  • MAX_SESSIONS: Por tenant. Balanço entre quota e recursos de servidor.
  • MJPEG: Codec ineficiente, alta CPU. Considerar HLS/WebRTC em próxima versão.
  • Xvfb: Sem hardware acceleration. GPU disabled no Chrome.
  • Single-threaded spawn: stopAllSessions() roda em série — lento em scale.
  • No session persistence: Profile é deletado. Cookies/localStorage perdidos.
