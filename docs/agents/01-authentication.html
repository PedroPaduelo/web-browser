Authentication Agent

Gerenciamento de autenticação e autorização com JWT para o sistema Serende

← Voltar para Documentação

Visão Geral

O Authentication Agent é responsável por todo o fluxo de autenticação e autorização do sistema Serende. Ele gerencia a geração e verificação de tokens JWT, deriva IDs de tenant a partir de API keys, e fornece middleware para proteger rotas da API. O agente opera de forma stateless, mantendo todas as informações necessárias no próprio token.

Funções Exportadas

auth.js
Função Parâmetros Retorno Descrição
generateToken String tenantId
Object options 		String Gera um token JWT com o tenantId e configurações de sessão. Inclui maxSessions no payload e define expiração baseada em JWT_EXPIRY (padrão: 24h). Retorna o token assinado.
verifyToken String token Object|null Verifica a assinatura e validade de um token JWT. Se válido, retorna o payload decodificado contendo tenantId, exp, maxSessions. Retorna null se inválido ou expirado.
deriveTenantId String apiKey String Deriva um tenantId único a partir de uma apiKey usando hash SHA256. Retorna os primeiros 16 caracteres do hash em hexadecimal. Idempotente: mesma API key sempre produz o mesmo tenantId.
authMiddleware Object req
Object res
Function next		 void Middleware Express que extrai o token do header Authorization: Bearer <token>, chama verifyToken, e popula req.tenant com o payload e req.user com info do tenant. Se inválido, retorna 401.

Variáveis de Ambiente

Variável Tipo Obrigatório Valor Padrão Descrição
JWT_SECRET String Sim - Chave secreta para assinatura de tokens JWT usando algoritmo HS256. Crítico para segurança: deve ser uma string longa e aleatória, mantida em segredo e diferente por ambiente. Se ausente, o agente falha na inicialização.
JWT_EXPIRY String Não 24h Tempo de expiração dos tokens JWT no formato aceito pelo jsonwebtoken (ex: 24h, 7d, 3600s). Aplica-se a todos os tokens gerados.

Riscos Conhecidos

Considerações de segurança e mitigações recomendadas para o agente de autenticação.

  • ⚠️

    JWT Hijacking / Token Theft

    Tokens JWT podem ser roubados via XSS, logs acidentais, ou interceptação de tráfego não-HTTPS. Mitigação: Use always HTTPS, expose tokens apenas em headers Authorization, implemente Revogação de Tokens via blacklist se necessário, e considere curta expiração com refresh tokens.

  • 🔓

    Vazamento de JWT_SECRET

    Se a variável JWT_SECRET for exposta, qualquer pessoa pode assinar tokens válidos, comprometendo completamente a segurança. Mitigação: Nunca commit secrets, use segredos diferentes por ambiente, e implemente rotação periódica com multiple secrets para validação.

  • 📊

    Derivação de TenantID com SHA256

    O uso de SHA256 puro para derivar tenantId a partir de apiKey pode permitir ataques de rainbow table se as API keys tiverem baixa entropia. Mitigação: Garanta que API keys sejam geradas com alta entropia (cryptographically random) e considere usar PBKDF2 ou Argon2 para derivação se necessário.

  • ⏱️

    Token Expiration e Clock Skew

    Diferentes servidores podem ter clocks ligeiramente dessincronizados (clock skew), causando rejeição de tokens ainda válidos. Mitigação: Considere adicionar um pequeno buffer (leeway) na verificação ou usar NTP para sincronização de tempo em todos os nós.

  • 🚫

    Falta de Revogação Imediata

    Tokens JWT são stateless e válidos até a expiração; não há como revogá-los antes sem estado adicional. Mitigação: Implemente um sistema de blacklist/token denylist no middleware, use short-lived tokens (1-2h) com refresh tokens, ou mude para sessions stateful se revogação em tempo real for crítica.
