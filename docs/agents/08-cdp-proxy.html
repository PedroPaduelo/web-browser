CDP Proxy Agent

Pool de conexoes WebSocket para Chrome DevTools Protocol, implementado em server/index.js.

Ativo

Visao Geral

O CDP Proxy Agent gerencia um pool de conexoes WebSocket por porta CDP. Quando um endpoint HTTP precisa interagir com o Chrome (screenshot, navegacao, execucao de script), ele usa o pool para reutilizar conexoes existentes ou criar novas, evitando overhead de handshake repetido.

Pool de Conexoes

Map<cdpPort, PoolState>

Estrutura do Pool

cdpPools: Map<number, { client: WebSocket, // conexao WS ativa ready: boolean, // true apos 'open' idCounter: number, // id incremental para JSON-RPC pendingRequests: Map<id, {resolve, reject}>, closeTimer: Timeout // auto-close 30s idle }>

Diagrama de Fluxo

Endpoint HTTP | v getCdpClient(cdpPort) | +-- pool existe e ready? | SIM --> limpa closeTimer, reinicia 30s, retorna pool | NAO --> GET http://127.0.0.1:{cdpPort}/json | | | v | encontra target type='page' | | | v | new WebSocket(webSocketDebuggerUrl) | | | +-- on('open') --> pool.ready = true, armazena no Map | +-- on('message') --> JSON.parse, resolve pendingRequests[id] | +-- on('close') --> limpa pool, rejeita todos pending | +-- on('error') --> rejeita se nao ready | v cdpRequest(cdpPort, method, params) | +-- id = pool.idCounter++ +-- pendingRequests.set(id, {resolve, reject}) +-- client.send(JSON.stringify({id, method, params})) +-- setTimeout 10s --> reject se ainda pending | v Resposta CDP --> resolve(result) ou reject(error)

Funcoes

API interna do proxy

getCdpClient(cdpPort)

Reutiliza conexao existente ou cria nova WebSocket para ws://127.0.0.1:{cdpPort}. Faz GET /json para descobrir o webSocketDebuggerUrl do page target. Registra listeners de message, close e error. Configura auto-close apos 30s de inatividade.

Retorna: Promise<PoolState>

closeCdpClient(cdpPort)

Fecha a conexao WebSocket e remove a entrada do pool. Chamada automaticamente pelo timer de idle ou quando uma sessao e destruida.

Retorna: void

cdpRequest(cdpPort, method, params)

Envia comando CDP via pool usando JSON-RPC. Gera id unico, registra em pendingRequests, envia pelo WebSocket e retorna Promise com timeout de 10s.

Retorna: Promise<any> (resultado CDP)

getPageTargetWsUrl(cdpPort)

Faz GET http://127.0.0.1:{cdpPort}/json, itera os targets retornados, encontra o de type='page' e retorna o campo webSocketDebuggerUrl.

Retorna: Promise<string | null>

Protocolo CDP

JSON-RPC sobre WebSocket

Formato de Comando

Cada comando CDP e uma mensagem JSON enviada pelo WebSocket com um id unico para correlacionar a resposta.

// Request (cliente -> Chrome) { "id": 1, "method": "Page.navigate", "params": { "url": "https://example.com" } } // Response (Chrome -> cliente) { "id": 1, "result": { "frameId": "ABC123", "loaderId": "XYZ789" } } // Error (Chrome -> cliente) { "id": 2, "error": { "code": -32000, "message": "Cannot navigate" } }

O listener on('message') faz JSON.parse, verifica se msg.id existe em pendingRequests, e resolve com msg.result ou rejeita com msg.error.message.

Endpoints

Rotas HTTP que usam o CDP Proxy
Rota Metodo HTTP Comando CDP Descricao

Timeout e Cleanup

Gerenciamento automatico de recursos

Estrategia de Lifecycle

T+0s
getCdpClient
Conexao WebSocket criada (ou reutilizada). Timer de idle iniciado: 30 segundos.
A cada request
getCdpClient
Timer de idle resetado para 30s. Conexao permanece viva enquanto houver atividade.
T+30s sem uso
closeCdpClient
Timer dispara. WebSocket e fechado via client.close(). Entrada removida do pool.
Sessao destruida
closeCdpClient
Chamada explicita ao destruir sessao. Garante limpeza imediata sem esperar o timer.

Timeouts

TipoDuracaoAcao
Conexao WS 10s Se o WebSocket nao emitir open em 10s, a Promise e rejeitada e o socket fechado.
Request CDP 10s Se a resposta nao chegar em 10s, o pending request e removido e a Promise rejeitada com "CDP request timeout".
Idle do pool 30s Sem requests por 30s, closeCdpClient e chamada automaticamente para fechar a conexao e liberar recursos.
