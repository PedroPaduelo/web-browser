Activity Tracker Agent

Rastreamento de atividade e gerenciamento de timeouts de sessão
Crítico

Visão Geral

O Activity Tracker Agent é implementado em session-manager.js e é responsável por rastrear a atividade da sessão do usuário e gerenciar timeouts automáticos. Garante a segurança e eficiência dos recursos encerrando sessões inativas após um período configurável.

Funções

API do Activity Tracker Agent
Função Descrição Parâmetros Retorno
startTimeoutTracker(sessionId) Inicia o rastreador de timeout para uma sessão. Define lastActivity como timestamp atual e inicia setInterval para verificação a cada 60s sessionId: string void
updateActivity(sessionId) Atualiza o timestamp de última atividade e reinicia o tracker. Usado pelo middleware trackActivity em cada request sessionId: string void
getSessionTimeout(sessionId) Retorna métricas de timeout para a sessão atual sessionId: string { inactive, remaining, timeoutMs, warningSoon }

Sistema de Warning

O Activity Tracker implementa um sistema de aviso antecipado para dar tempo de resposta antes do timeout automático. A janela de warning é configurável através da constante TIMEOUT_WARNING_MS.

// Constante de warning (2 minutos antes do timeout) const TIMEOUT_WARNING_MS = 2 * 60 * 1000; // 120000 ms // Lógica de detecção de warning const timeUntilTimeout = SESSION_TIMEOUT_MS - inactiveTime; const isWarningThreshold = timeUntilTimeout <= TIMEOUT_WARNING_MS; if (isWarningThreshold) { console.warn(`[ActivityTracker] Session ${sessionId} approaching timeout in ${Math.round(timeUntilTimeout / 1000)}s`); if (config.onTimeoutWarning) { config.onTimeoutWarning(sessionId, timeUntilTimeout); } }

Comportamento do Warning

  • Log dewarning no console quando a sessão está a 2 minutos do timeout
  • Callback onTimeoutWarning é disparado se configurado no session config
  • Pode ser usado para notificar o frontend ou salvar progresso automático
  • Sessão continua ativa até o timeout real ser atingido

Constantes de Timeout

Os valores de timeout são configuráveis através de variáveis de ambiente ou configuração de sessão.

// session-manager.js - Timeout configuration const SESSION_TIMEOUT_MINUTES = parseInt(process.env.SESSION_TIMEOUT_MINUTES || '30', 10); const SESSION_TIMEOUT_MS = SESSION_TIMEOUT_MINUTES * 60 * 1000; // 30min default const TIMEOUT_WARNING_MS = 2 * 60 * 1000; // 2 minutos antes // Intervalo de verificação (não configurável, fixo em 60s) const TIMEOUT_CHECK_INTERVAL = 60 * 1000;

Configuração por Ambiente

  • .env: SESSION_TIMEOUT_MINUTES=30
  • Desenvolvimento: Pode ser reduzido para 5-10 minutos
  • Produção: Recomendado 30 minutos para sessões de usuário
  • Ambientes sensíveis: Pode ser aumentado para até 60 minutos

Detalhes de Implementação

Como o tracking funciona internamente

Estrutura de Dados da Sessão

session.timeoutTracker = { intervalId: null, // ID do setInterval lastActivity: timestamp, // Última vez que updateActivity foi chamado warningEmitted: false, // Flag para evitar múltiplos warnings config: { timeoutMs: 1800000, // SESSION_TIMEOUT_MS warningMs: 120000, // TIMEOUT_WARNING_MS checkInterval: 60000, // 60 segundos onTimeoutWarning: fn // Callback opcional } }

Ciclo de Check Interval

// Implementação simplificada do check loop function checkTimeouts() { const now = Date.now(); for (const [sessionId, session] of sessions) { if (!session.timeoutTracker) continue; const { lastActivity } = session.timeoutTracker; const inactive = now - lastActivity; const timeoutMs = SESSION_TIMEOUT_MS; const warningThreshold = timeoutMs - TIMEOUT_WARNING_MS; // Verifica warning threshold if (inactive >= warningThreshold && inactive < timeoutMs) { if (!session.timeoutTracker.warningEmitted) { emitWarning(sessionId, timeoutMs - inactive); session.timeoutTracker.warningEmitted = true; } } // Verifica timeout real if (inactive >= timeoutMs) { stopSession(sessionId, 'timeout'); } } } // Iniciado em startTimeoutTracker setInterval(checkTimeouts, TIMEOUT_CHECK_INTERVAL);

Tratamento de Erros

O Activity Tracker inclui mecanismos de recuperação para cenários de erro.

// startTimeoutTracker com validação function startTimeoutTracker(sessionId) { const session = getSession(sessionId); if (!session) { throw new Error(`Session ${sessionId} not found`); } if (session.timeoutTracker?.intervalId) { clearTimeoutTracker(sessionId); // Limpa tracker existente primeiro } session.timeoutTracker = { intervalId: setInterval(() => checkSessionTimeout(sessionId), TIMEOUT_CHECK_INTERVAL), lastActivity: Date.now(), warningEmitted: false }; } // Proteção no updateActivity function updateActivity(sessionId) { const session = getSession(sessionId); if (!session?.timeoutTracker) { // Sessão sem tracker - pode ter sido limpa, log mas não falha console.warn(`[ActivityTracker] Session ${sessionId} has no tracker`); return; } session.timeoutTracker.lastActivity = Date.now(); session.timeoutTracker.warningEmitted = false; // Reset do warning }

Considerações de Performance

Performance do setInterval

  • Check interval de 60s é balanceado entre responsividade e overhead
  • A verificação percorre todas as sessões ativas - custo O(n)
  • Para 1000 sessões, overhead é ~1-2ms por verificação
  • Considerar clustering para alta escala (>10k sessões simultâneas)

Memória

  • Cada sessão armazena: intervalId (~8 bytes), lastActivity (8 bytes), 2 flags
  • Overhead total: ~30-50 bytes por sessão
  • Interval IDs são limpos quando a sessão é encerrada
  • Memory leak protection: clearTimeoutTracker em stopSession
