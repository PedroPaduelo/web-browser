Chrome Process Agent

Ativo

Agente responsável por gerenciar o ciclo de vida do Chrome headless, incluindo spawn e monitoramento via CDP.

Visão Geral

Implementado em session-manager.js, o Chrome Process Agent é responsável por criar, configurar e gerenciar instâncias do navegador Chrome em modo headless. Gerencia todo o lifecycle do processo, desde o spawn inicial até o encerramento, monitorando a conectividade via Chrome DevTools Protocol (CDP) e lidando com eventos de saída.

Startup Sequence

Sequência de inicialização do processo Chrome:

1
Preparação das Variáveis de Ambiente
Configura LD_LIBRARY_PATH e variáveis necessárias para a biblioteca do Chrome antes do spawn.
2
Spawn do Processo
Executa chrome-install/opt/google/chrome/google-chrome com os arguments configurados.
3
Initial Handshake
Processo Chrome é iniciado e começa a escutar na porta de debugging configurada.
4
CDP Polling
Agente verifica se o endpoint /json/version está respondendo (ver seção abaixo).
5
Ready
Chrome está pronto para receber comandos via CDP. Sessão é marcada como ativa.

CDP Readiness

O agente aguarda o Chrome estar pronto para conexão CDP através de polling no endpoint /json/version:

1. Inicia polling: GET http://127.0.0.1:/json/version 2. Intervalo: 500ms entre tentativas 3. Máximo de tentativas: 15 4. Timeout total: 7.5 segundos 5. Se sucesso: CDP pronto, retorna WebSocket URL 6. Se falhar após 15 tentativas: erro de timeout, sessão abortada
t = 0ms
Chrome Process Agent
Inicia Chrome com remote-debugging-port configurado
t = ~500-1500ms
Chrome
Processo inicializado, endpoint /json/version disponível
t = Primeiro sucesso polling
Chrome Process Agent
Recebe resposta JSON com WebSocketURL, CDP conectado
t = Pronto
Sistema
Sessão ativa e pronta para execução de páginas

Environment Configuration

O agente configura LD_LIBRARY_PATH para garantir que o Chrome encontre suas bibliotecas compartilhadas no ambiente containerizado:

LD_LIBRARY_PATH="/chrome-install/opt:/chrome-install/usr/lib:${LD_LIBRARY_PATH}" export LD_LIBRARY_PATH

Caminhos configurados:

  • /chrome-install/opt - Biblioteca principal do Chrome
  • /chrome-install/usr/lib - Bibliotecas do sistema do Chrome

Exit Handler

O agente monitora o evento exit do processo Chrome para clean-up e notificação:

Chrome Process
Emite evento 'exit' com código de saída
Exit Handler
Recebe evento, chama stopSession()
Stop Session
Limpa recursos, encerra conexões CDP
Callback
Invoca onSessionDiedCallback com código de saída
Session Manager
Remove sessição do pool ativo, decide se deve recriar

Error Handling

O agente lida com diferentes cenários de falha durante o lifecycle do Chrome:

Exit Codes Comuns

  • 0 - Encerramento normal (sessão finalizada por usuário)
  • 1 - Erro genérico (crash ou initial failure)
  • Signal-based - Processo morto por signal (SIGKILL, SIGTERM, etc.)
  • null - Processo terminado inesperadamente (kill -9)

Timeout CDP: Se o polling não obtiver resposta em 7.5s, a sessão é marcada como falha e o processo é killado automaticamente.

Spawn Failure: Se o Chrome não iniciar (executable inválido ou permissões), o erro é propagado para o Session Manager.

Unexpected Exit: Quando o Chrome crasha durante execução, o onSessionDiedCallback é invocado e o Session Manager pode optar por recriar a sessão automaticamente.
