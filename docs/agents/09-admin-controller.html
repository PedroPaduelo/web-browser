Visão Geral

O Admin Controller Agent é implementado no index.js e gerencia todas as rotas sob o prefixo /api/admin/*. Essas rotas são protegidas pelo middleware adminAuth, garantindo que apenas administradores autenticados possam acessar as funcionalidades de gerenciamento do sistema.

Autenticação Admin

Middleware adminAuth

O middleware adminAuth é responsável por verificar a autenticação de todos os endpoints administrativos. Ele utiliza comparação timing-safe para prevenir ataques de timing side-channel.

┌─────────────────────────────────────────────────────────────┐ │ Fluxo adminAuth │ ├─────────────────────────────────────────────────────────────┤ │ │ │ 1. Extrai header "x-admin-secret" da requisição │ │ │ │ 2. Verifica se ADMIN_SECRET está configurado no .env │ │ ├─ NÃO → Retorna 403 (Forbidden) │ │ └─ SIM → Continua para passo 3 │ │ │ │ 3.Compara usando crypto.timingSafeEqual() │ │ ├─ IGUAIS → Passa req.admin = true → next() │ │ └─ DIFERENTES → Retorna 401 (Unauthorized) │ │ │ └─────────────────────────────────────────────────────────────┘
// Implementação do middleware adminAuth const adminAuth = (req, res, next) => { const { ADMIN_SECRET } = process.env; // Verifica se a variável de ambiente está configurada if (!ADMIN_SECRET) { return res.status(403).json({ error: 'Admin authentication not configured', message: 'ADMIN_SECRET environment variable is required' }); } const providedSecret = req.headers['x-admin-secret']; if (!providedSecret) { return res.status(401).json({ error: 'No admin secret provided', message: 'Missing x-admin-secret header' }); } // Comparação segura contra timing attacks const isValid = crypto.timingSafeEqual( Buffer.from(providedSecret), Buffer.from(ADMIN_SECRET) ); if (!isValid) { return res.status(401).json({ error: 'Invalid admin credentials', message: 'The provided admin secret is incorrect' }); } req.admin = true; next(); };
⚠️ Segurança: Configure ADMIN_SECRET como string longa e aleatória

Endpoints

Método Rota Resposta Descrição

Detalhes dos Endpoints

1
Criar API Key
POST /api/admin/keys

Cria uma nova API key para um tenant. A key gerada é retornada apenas uma vez no campo value. O campo features é um objeto que controla quais módulos o tenant pode acessar por sessão.

Request Body

{ "name": "string - Nome descritivo da key", "maxSessions": "number - Sessões simultâneas permitidas", "maxSessionDuration": "number - Duração máxima em segundos", "maxIdleTimeout": "number - Timeout de inatividade em ms", "features": { "uploadFiles": "boolean", "console": "boolean", "screenshot": "boolean", "video": "boolean", "domTracker": "boolean" } }

Response

{ "id": "uuid-v4", "name": "string", "enabled": true, "maxSessions": 5, "maxSessionDuration": 3600, "maxIdleTimeout": 300000, "features": {...}, "createdAt": "ISO 8601", "updatedAt": "ISO 8601", "value": "sk_live_xxx - APENAS NA CRIAÇÃO" }
2
Listar API Keys
GET /api/admin/keys

Retorna todas as API keys cadastradas. Por segurança, o valor completo da key não é incluído na resposta. Apenas os primeiros e últimos caracteres são mostrados para identificação.

{ "keys": [ { "id": "uuid-v4", "name": "string", "keyPreview": "sk_live_xxxx...xxxx", "enabled": true, "maxSessions": 5, "maxSessionDuration": 3600, "maxIdleTimeout": 300000, "features": {...}, "createdAt": "ISO 8601", "updatedAt": "ISO 8601" } ] }
3
Atualizar Configuração
PATCH /api/admin/keys/:id

Atualiza as configurações de uma API key existente. Campos opcionais podem ser enviados separadamente. O campo enabled permite desabilitar uma key sem removê-la (recomendado).

{ "name": "optional - novo nome", "enabled": "optional - boolean", "maxSessions": "optional - number", "maxSessionDuration": "optional - number", "maxIdleTimeout": "optional - number", "features": "optional - objeto parcial" }
4
Regenerar Key
POST /api/admin/keys/:id/regenerate

Gera um novo valor para a API key mantendo o mesmo ID e todas as configurações. O novo valor é retornado apenas nesta requisição. Use em caso de vazamento suspeito.

{ "id": "uuid-v4 (mantido)", "name": "string (mantido)", "value": "sk_live_novo_valor_xxx", "updatedAt": "ISO 8601" }
5
Revogar Key
DELETE /api/admin/keys/:id

Revoga uma API key definindo enabled = false. A key não é excluída do banco, preservando o histórico de uso para auditoria. Sessões ativas usando essa key continuam funcionando até expirar.

{ "id": "uuid-v4", "message": "API key revoked successfully", "revokedAt": "ISO 8601" }
6
Listar Sessões
GET /api/admin/sessions

Retorna todas as sessões ativas no sistema, incluindo o nome do tenant associado e informações detalhadas sobre timeout (restante, idle, total).

{ "sessions": [ { "sessionId": "uuid", "tenantName": "Nome do Tenant", "apiKeyId": "uuid", "featuresUsed": ["console", "screenshot", ...], "expiresAt": "ISO 8601", "idleTimeout": 300000, "remainingTime": 245, "idleTimeRemaining": 180, "totalDuration": 120, "url": "https://exemplo.com", "createdAt": "ISO 8601" } ], "total": 15 }
7
Estatísticas do Sistema
GET /api/admin/stats

Retorna estatísticas agregadas sobre o sistema, incluindo contadores de keys, sessões ativas e informações de uptime do serviço.

{ "totalKeys": 25, "activeKeys": 18, "disabledKeys": 7, "totalActiveSessions": 42, "maxSessionsGlobal": 100, "uptime": { "seconds": 86400, "formatted": "1d 0h 0m 0s" }, "generatedAt": "ISO 8601" }

Frontend Admin

Painel de Administração React

A interface administrativa está disponível na rota /admin do frontend React. O componente principal é AdminPanel.tsx, que oferece uma interface completa para gerenciamento de API keys e monitoramento de sessões.

Funcionalidades

  • Listagem completa de API keys com preview seguro
  • Criação de novas chaves com validação de features
  • Edição inline de configurações (maxSessions, timeouts)
  • Regeneração de chaves com confirmação
  • Revogação com preservação de histórico
  • Tabela de sessões ativas com filtros
  • Dashboard de estatísticas em tempo real
  • Indicadores visuais de status (ativo/desabilitado)

Exemplos cURL

Listar todas as keys

curl -X GET "http://localhost:3000/api/admin/keys" \ -H "x-admin-secret: sua_chave_secreta_admin"

Criar nova API key

curl -X POST "http://localhost:3000/api/admin/keys" \ -H "x-admin-secret: sua_chave_secreta_admin" \ -H "Content-Type: application/json" \ -d '{ "name": "Cliente Enterprise", "maxSessions": 10, "maxSessionDuration": 7200, "maxIdleTimeout": 600000, "features": { "uploadFiles": true, "console": true, "screenshot": true, "video": false, "domTracker": true } }'

Atualizar configuração da key

curl -X PATCH "http://localhost:3000/api/admin/keys/abc123-def456-ghi789" \ -H "x-admin-secret: sua_chave_secreta_admin" \ -H "Content-Type: application/json" \ -d '{ "maxSessions": 5, "enabled": true }'

Regenerar key

curl -X POST "http://localhost:3000/api/admin/keys/abc123-def456-ghi789/regenerate" \ -H "x-admin-secret: sua_chave_secreta_admin"

Revogar key

curl -X DELETE "http://localhost:3000/api/admin/keys/abc123-def456-ghi789" \ -H "x-admin-secret: sua_chave_secreta_admin"

Listar sessões ativas

curl -X GET "http://localhost:3000/api/admin/sessions" \ -H "x-admin-secret: sua_chave_secreta_admin"

Obter estatísticas

curl -X GET "http://localhost:3000/api/admin/stats" \ -H "x-admin-secret: sua_chave_secreta_admin"

Considerações de Segurança

!
Práticas Recomendadas
Configuração Inicial
ADMIN_SECRET
Use uma string longa e aleatória (mínimo 32 caracteres). Configure apenas no ambiente de produção, nunca no código.
Header x-admin-secret
HTTPS Required
Sempre use HTTPS para transmitir o header. Em desenvolvimento local HTTP é aceito, mas nunca em produção.
Revogação
DELETE vs PATCH
Prefira PATCH com enabled=false para manter histórico. Use DELETE apenas para remover dados comprometidos.
Regeneração
Vazamento Suspeito
Use POST /regenerate para gerar nova key. Notifique o tenant imediatamente sobre a mudança.
Auditoria
Logs
Todas as ações administrativas devem ser logadas com timestamp, admin-id e IP de origem.
