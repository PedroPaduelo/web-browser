Módulo 5: Visualização Remota de Browser

Entenda como o streaming MJPEG funciona, como consumir a imagem no frontend, otimizações e limitações do protocolo.

Duração estimada25 minutos
DificuldadeBásico
Pré-requisitosMódulo 4 (sessão ativa)

🎯 Objetivos deste módulo

  • Compreender o formato MJPEG e boundary streaming

    Como o FFmpeg emite frames via multipart/x-mixed-replace.

  • Aprender a consumir o stream no frontend

    Uso de <img>, fetch+blob, ou WebSocket alternativo.

  • Conhecer as limitações de latência e qualidade

    Por que MJPEG não é adequado para vídeos e jogos.

  • Saber configurar resolução e FPS

    Impacto da largura/altura e frame rate na performance.

📺 O que é MJPEG streaming?

MJPEG (Motion JPEG) é um fluxo contínuo de quadros JPEG individuais enviados via HTTP como multipart/x-mixed-replace. Cada frame é uma imagem completa (não interframe).

Fluxo do FFmpeg

ffmpeg -f x11grab -video_size 1280x720 -framerate 15 -i :99.0 -fmjpeg -q:v 5 -
Captura tela do Xvfb display :99, 15 FPS, qualidade 5 (1-31, menor=melhor), envia para stdout.

Formato HTTP

HTTP/1.1 200 OK
Content-Type: multipart/x-mixed-replace;boundary=frame

--frame
Content-Type: image/jpeg
Content-Length: 48321

<bytes JPEG>
--frame
Content-Type: image/jpeg
Content-Length: 47502

<bytes JPEG>
...

O cliente mantém a conexão aberta e renderiza cada parte como um novo frame.

🖼️ Consumindo o Stream no Frontend

Método 1: <img> tag (simples)

// React component
export function BrowserViewer({ sessionId, token }) {
  const streamUrl = `/api/sessions/${sessionId}/stream?token=${token}`;

  return (
    <div className="viewer">
      <img
        src={streamUrl}
        alt="Browser remoto"
        style={{ width: '100%', height: 'auto' }}
        onLoad={() => console.log('Stream conectado')}
        onError={(e) => console.error('Stream falhou', e)}
      />
    </div>
  );
}
Vantagem: Simplicidade. Navegador lida automaticamente com multipart.
Desvantagem: Não controla FPS, não retrocede, Buffer mínimo.

Método 2: fetch() + Blob (mais controle)

async function startStream(sessionId, token) {
  const url = `/api/sessions/${sessionId}/stream?token=${token}`;
  const res = await fetch(url);
  const reader = res.body.getReader();

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

  }

Nota: O parse manual de multipart é complexo. Use <img> na maioria dos casos.

Método 3: WebSocket (opcional, se implementado)

Algumas implementações expõem ws://server/ws/stream?session=... enviando frames MJPEG binários. Consulte config.

⚙️ Configurando Resolução e FPS

A qualidade do streaming é determinada no momento da criação da sessão. O Session Manager passa parâmetros para o FFmpeg.

Parâmetros de criação de sessão

CampoTipoPadrãoDescrição
widthnumber1280Largura em pixels. Valores comuns: 800, 1024, 1280, 1920.
heightnumber720Altura em pixels. Valores comuns: 600, 720, 1080.
fpsnumber15Frame rate. Máximo prático: 30 FPS (maior consome CPU).
qualitynumber5Qualidade FFmpeg (1-31, menor=melhor). 2-5 é boa.

Exemplo de criação com parâmetros customizados

POST /api/sessions
{
  "url": "https://example.com",
  "width": 1920,
  "height": 1080,
  "fps": 20,
  "quality": 3
}

📊 Latência e Performance

Componentes da latência

  • Capture (Xvfb → FFmpeg): 1–5 ms
  • Encode (FFmpeg JPEG): 10–30 ms
  • Network (server → client): 10–100 ms (depende da rede)
  • Render (navegador): 5–15 ms
  • Total típico: 80–150 ms round-trip

FPS observado

O FFmpeg tenta manter o -framerate configurado, mas o ritmo é limitado pelo encode e pela rede. Em redes locais: 12–15 FPS. Em redes remotas com alta latência: pode cair para 5–8 FPS.

⚠️ Limite de MJPEG: Cada frame é uma imagem completa (independente). Isso consome mais largura de banda que H.264/AV1. É adequado para controle manual, não para vídeos longos.

🔧 Solução de Problemas de Streaming

❌ A imagem não aparece (broken ou vazia)

Causas comuns:

  • Sessão ainda não inicializou (Chrome/FFmpeg não estão prontos). Aguarde 3–5 segundos após criação.
  • Token expirado ou inválido.
  • CORS bloqueando (se frontend em domínio diferente). Verifique CORS_ORIGIN.
  • FFmpeg crash. Verifique logs do servidor.

❌ Streaming muito lento ou com frames congelados

Causas:

  • Resolução/FPS muito altos para o CPU disponível.
  • Rede instável (alta perda de pacotes).
  • Processo FFmpeg consumindo 100% CPU — usar qualidade mais baixa (quality: 7).

❌ Erro 404 ou 403 no /stream

Verifique:

  • Session ID correto.
  • Token válido e não expirado.
  • Session não foi encerrada por timeout.

🔍 Diagnóstico via logs

pm2 logs serende | grep -E "(ffmpeg|stream|session.*sess_)"

💡 Otimizações Recomendadas

  • Use resolução mínima necessária. Para formulários web, 1024×768 é suficiente.
  • Reduza FPS para 10 em aplicações que não precisam de movimento rápido.
  • Ajuste quality entre 5 e 8 — qualidade acima de 5 melhora pouco e dobra CPU.
  • Habilite DISPLAY_BASE no .env para evitar conflitos de Xvfb.
  • Monitore uso de CPU; se estiver alto, reduza resolução/FPS.
  • Em produção, use Nginx como proxy reverso com gzip desabilitado (já é JPEG).
