Módulo 4: Gerenciamento de Sessões

Aprenda a criar, monitorar e encerrar sessões de browser remoto, entender o ciclo de vida e os recursos envolvidos.

Duração estimada30 minutos
DificuldadeIntermediário
Pré-requisitosMódulos 1-3

🎯 Objetivos deste módulo

  • Compreender o ciclo de vida de uma sessão

    Criação → Ativa → Timeout/Encerramento → Cleanup.

  • Saber criar e encerrar sessões via API

    Endpoints REST para gerenciar sessões.

  • Entender os recursos envolvidos

    Xvfb, Chrome, FFmpeg — quanto memória e CPU cada um consome.

  • Configurar timeout e cleanup

    SESSION_TIMEOUT_MS e cleanup de processos órfãos.

🔄 Ciclo de Vida de uma Sessão

1. Solicitação de criação POST /api/sessions com Authorization: Bearer <token>

Session Manager recebe a requisição e deriva o tenantId do token JWT.

2. Alocação de display (Xvfb) ~500ms

Session Manager aloca um display livre do pool (ex: :99, :100, :101...). Inicia Xvfb com resolução configurável (padrão: 1280x720).

3. Inicialização do Chrome ~3-5 segundos

Chrome é iniciado com flags headless, sandbox desabilitado, e remote-debugging-port=9222+N (ex: 9222, 9223...). O Chrome pointeda para o DISPLAY alocado.

4. Inicialização do FFmpeg ~1 segundo

FFmpeg captura a tela via x11grab do Xvfb (ex: -i :99.0) e codifica em MJPEG, multipart/x-mixed-replace.

5. Sessão ativa Até timeout ou DELETE

A sessão está pronta. Frontend pode: (a) consumir stream MJPEG, (b) enviar inputs via POST ou WS, (c) executar comandos CDP.

6. Timeout ou encerramento padrão: 6 minutos de inatividade

Session Manager verificaActivityTracker. Se não há atividade, a sessão é encerrada automaticamente.

7. Cleanup ~1 segundo

Processos (Xvfb, Chrome, FFmpeg) são terminados (kill). Recursos são liberados. Display retorna ao pool.

📡 API de Sessões

Criar Sessão

POST /api/sessions
Authorization: Bearer <token>
Content-Type: application/json

{
  "url": "https://example.com",        // URL inicial (opcional)
  "width": 1280,                       // Largura (opcional, padrão: 1280)
  "height": 720,                       // Altura (opcional, padrão: 720)
  "profileId": "meu-perfil",           // ID do perfil (opcional)
  "record": false                      // Gravar sessão (opcional)
}

Resposta (200):

{
  "sessionId": "sess_abc123def456",
  "tenantId": "acme-corp",
  "display": ":100",
  "cdpPort": 9223,
  "streamUrl": "http://server:3333/api/sessions/sess_abc123def456/stream",
  "wsUrl": "ws://server:3333/ws/stream?session=sess_abc123def456",
  "inputWsUrl": "ws://server:3333/ws/input?session=sess_abc123def456"
}

Listar Sessões Ativas

GET /api/sessions
Authorization: Bearer <token>

Resposta (200):

{
  "sessions": [
    {
      "sessionId": "sess_abc123",
      "tenantId": "acme-corp",
      "url": "https://google.com",
      "display": ":100",
      "cdpPort": 9223,
      "createdAt": "2024-01-15T10:30:00Z",
      "lastActivity": "2024-01-15T10:35:00Z"
    }

}

Obter Status de Uma Sessão

GET /api/sessions/:sessionId
Authorization: Bearer <token>

Encerrar Sessão

DELETE /api/sessions/:sessionId
Authorization: Bearer <token>

Resposta (200):

{"message": "Session sess_abc123def456 terminated"}

Navegar para Nova URL

POST /api/sessions/:sessionId/navigate
Authorization: Bearer <token>
Content-Type: application/json

{"url": "https://novaurl.com"}

⚙️ Configuração de Timeout

VariávelDefaultDescrição
SESSION_TIMEOUT_MS360000 (6 min)Tempo máximo sem atividade antes de encerrar a sessão.
IDLE_CHECK_INTERVAL_MS30000 (30 seg)Frequência com que o Session Manager verifica sessões órfãs.
⚠️ Importante: O timeout é baseado em atividade — não apenas tempo desde a criação. Cada input (mouse, teclado) reseta o timer. Sessões sem input por 6 minutos são encerradas automaticamente para liberar recursos.

💻 Criar Sessão — Exemplo Completo com curl

# 1. Login para obter token
TOKEN=$(curl -s -X POST http://localhost:3333/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"apiKey":"sk_demo_abc123"}' | jq -r .token)

# 2. Criar sessão
SESSION=$(curl -s -X POST http://localhost:3333/api/sessions \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com"}')

echo "$SESSION" | jq .

# Saída:
# {
#   "sessionId": "sess_xyz789",
#   "display": ":100",
#   "cdpPort": 9223,
#   "streamUrl": "http://localhost:3333/api/sessions/sess_xyz789/stream"
# }

# 3. Baixar stream (teste)
curl -H "Authorization: Bearer $TOKEN" \
  "http://localhost:3333/api/sessions/sess_xyz789/stream" \
  --output test.mjpeg

# 4. Encerrar sessão
curl -X DELETE http://localhost:3333/api/sessions/sess_xyz789 \
  -H "Authorization: Bearer $TOKEN"

🔍 Monitoramento de Sessões

Verificar processos da sessão

# Listar todos os processos relacionados
ps aux | grep -E "(Xvfb|chrome|ffmpeg)" | grep -v grep

# Verificar consumo de memória
ps aux --sort=-rss | head -20 | grep -E "(Xvfb|chrome)"


        
Métricas via API Admin

        
# Requer ADMIN_SECRET no header
curl http://localhost:3333/api/admin/stats \
  -H "x-admin-secret: $ADMIN_SECRET"

        
Retorna contagem de sessões ativas, memória total, e uptime.


        
Eventos SSE (Server-Sent Events)

        
# Receber eventos de atividade em tempo real
curl -N http://localhost:3333/api/sessions/events \
  -H "Authorization: Bearer $TOKEN"

        
Eventos: session_created, session_ended, activity.

⚠️ Limites e Boas Práticas

  • Recursos por sessão: ~200-400 MB RAM (Chrome ~150MB, Xvfb ~30MB, FFmpeg ~20MB).
  • Limite de sessões simultâneas: depends on server RAM. Regra prática: 1GB RAM = ~3-4 sessões.
  • Sessions não são persistidas: Se o servidor reiniciar, todas as sessões são perdidas.
  • Encerramento limpo: Sempre use DELETE /api/sessions/:id para encerrar. Não kill -9.
  • Use timeout curto em produção: 6 min é suficiente para a maioria dos casos de uso.
