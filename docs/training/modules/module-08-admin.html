Módulo 8: Administração, Monitoramento e Segurança

Domine o painel admin, monitore sessões em tempo real, gerencie chaves API, e entenda as camadas de segurança do Serende.

Duração estimada35 minutos
DificuldadeAvançado
Pré-requisitosMódulos 1-7

🎯 Objetivos deste módulo

  • Usar o painel admin do React

    Interface web para gerenciar chaves e sessões.

  • Gerenciar chaves API via REST

    Criar, listar, revogar e regenerar chaves.

  • Monitorar sessões ativas

    Ver status, encerrar sessões problemáticas.

  • Entender as camadas de segurança

    Helmet, CORS, Rate Limiting, JWT, autenticação de admin.

  • Configurar monitoramento e alertas

    Logs estruturados, métricas, health checks.

🛡️ Painel Admin

O Serende inclui um painel admin em React na rota /admin do frontend.

Acesso

  1. Acesse https://serende.example.com/admin
  2. Insira o ADMIN_SECRET (definido no .env)
  3. Navegue pelas abas: Chaves, Sessões, Métricas
Nota: O Admin Secret é enviado via header x-admin-secret. Ele é diferente do JWT usado por tenants normais.

🔑 Gestão de Chaves API

Endpoints Admin

MétodoRotaDescrição
POST/api/admin/keysCriar nova chave API
GET/api/admin/keysListar todas as chaves
PATCH/api/admin/keys/:idAtualizar metadados de uma chave
POST/api/admin/keys/:id/regenerateRegenerar chave (invalida a anterior)
DELETE/api/admin/keys/:idRevogar chave

Criar chave via API

curl -X POST http://localhost:3333/api/admin/keys \
  -H "x-admin-secret: $ADMIN_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"tenantId":"acme-corp","label":"Chave de produção"}'

Resposta:

{
  "id": "key_abc123",
  "tenantId": "acme-corp",
  "apiKey": "sk_acme_8f3e2a1b9c4d...",
  "label": "Chave de produção",
  "createdAt": "2024-01-15T10:00:00Z"
}
⚠️ ATENÇÃO: A apiKey só é retornada na criação. Após isso, apenas o hash é armazenado. Se perdida, use POST /api/admin/keys/:id/regenerate.

Listar chaves

curl http://localhost:3333/api/admin/keys \
  -H "x-admin-secret: $ADMIN_SECRET"

Revogar chave

curl -X DELETE http://localhost:3333/api/admin/keys/key_abc123 \
  -H "x-admin-secret: $ADMIN_SECRET"

🔒 Camadas de Segurança

O Security Middleware Agent (10-security-middleware) implementa 10 layers de proteção:

#MiddlewareFunção
1Trust ProxyConfia em headers X-Forwarded-For (se atrás de proxy)
2HelmetHeaders de segurança (X-Frame-Options, X-Content-Type, etc.)
3CORSControle de origem cruzada (configurável via CORS_ORIGIN)
4Body ParserJSON com limite de tamanho (10MB padrão)
5Rate Limit Global100 req/min por IP (configurável)
6Request IDUUID para rastreamento de requisições nos logs
7Login Rate Limiter5 tentativas de login por IP a cada 60 segundos
8Structured LoggingLogs JSON com timestamp, request ID, status
9Error HandlerErros padronizados (produção não expõe stack traces)
10404 HandlerRespostas JSON padronizadas para rotas inexistentes

⚠️ Riscos Conhecidos e Mitigações

🔴 Riscos Críticos

RiscoImpactoMitigação
JWT HijackingAcesso a sessão alheiaHTTPS obrigatório, tokens com expiração curta
Vazamento de ADMIN_SECRETControle total do sistemaArmazene em cofre de segredos, nunca em código
Key store SQLite corrompidoPerda de todas as chavesBackup regular do data/key-store.db
Escape do XvfbAcesso ao display hostChrome com --no-sandbox, isolamento de processos

📋 Logs Estruturados

Formato de log

{
  "level": "info",
  "timestamp": "2024-01-15T10:30:00.123Z",
  "requestId": "uuid-...",
  "method": "POST",
  "url": "/api/sessions",
  "statusCode": 200,
  "responseTime": 1523,
  "tenantId": "acme-corp",
  "ip": "192.168.1.1"
}

Visualizar logs em produção

# PM2 — últimas 50 linhas
pm2 logs serende --lines 50

# Logs contínuos (follow)
pm2 logs serende

# Filtrar erros
pm2 logs serende | grep '"level":"error"'

# Logs de uma sessão específica
pm2 logs serende | grep "sess_abc123"

Health Check Endpoint

curl http://localhost:3333/health

Retorna {"status":"ok","timestamp":"..."} se o servidor está operacional.
