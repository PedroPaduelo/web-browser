Módulo 7: Streaming (Vídeo/Áudio) e Áudio Opcional

Entenda como o vídeo é codificado e transmitido, e como habilitar áudio quando necessário. Módulo cobre FFmpeg e Audio Manager.

🎬 Streaming de Vídeo (MJPEG)

O vídeo do browser é capturado do framebuffer Xvfb e codificado em tempo real pelo FFmpeg.

Pipeline detalhado

┌─────────────────────────────────────────────────────────────────────────┐ │ Xvfb (framebuffer :99) │ │ ┌─────────────────────────────────────────────────────────────────┐ │ │ │ Renderização do Chrome (headless) │ │ │ └─────────────────────────────────────────────────────────────────┘ │ │ ▲ │ │ │ x11grab │ │ │ │ │ ┌──────┴──────────────────┐ │ │ │ FFmpeg │ │ │ │ -f x11grab │ │ │ │ -video_size WxH │ │ │ │ -framerate N │ │ │ │ -i :99.0 │ │ │ │ -f mjpeg │ │ │ │ -q:v 5 │ │ │ │ - │ │ │ └──────┬──────────────────┘ │ │ │ stdout (multipart/x-mixed-replace) │ │ ▼ │ │ Fastify route: GET /api/sessions/:id/stream │ │ │ │ │ ▼ │ │ Cliente <img src="/api/..."> (MJPEG multipart streaming) │ └─────────────────────────────────────────────────────────────────────────┘

Parâmetros FFmpeg por sessão

ParâmetroValor padrãoDescrição
-f x11grabfixoFonte de captura do Xvfb.
-video_size1280x720Resolução, herdada da sessão.
-framerate15Frames por segundo (1–30).
-i :99.0display varDisplay Xvfb (promovido por DISPLAY_BASE).
-f mjpegfixoFormato de saída.
-q:v5Qualidade (1–31, menor = melhor).

⚙️ Configuração de Streaming

As propriedades são passadas no POST /api/sessions.

Campos opcionais da criação de sessão

CampoTipoPadrãoImpacto
widthnumber1280+resolução = +largura de banda
heightnumber720 mesma coisa
fpsnumber15+FPS = +CPU e +banda
quality1–315Menor = melhor qualidade, mais CPU

Exemplo com streaming otimizado

POST /api/sessions
{
  "url": "https://example.com",
  "width": 1024,
  "height": 768,
  "fps": 12,
  "quality": 7
}
⚠️ Atenção: MJPEG não é adequado para vídeos longos, Netflix, YouTube. Use apenas para controle e navegação. A latência típica é de 80–150 ms.

🔊 Áudio (Opcional)

O Serende suporta captura de áudio do Chrome via WebRTC/audio-capture (experimental). Requer o Audio Manager Agent ativo.

Importante: O áudio NÃO é mixado no MJPEG. Ele é fornecido via endpoint separado, geralmente via SSE ou WAV/PCM stream.

Como habilitar

POST /api/sessions
{
  "url": "https://example.com",
  "audio": true   // ou "wav" ou "pcm"
}

Endpoint de áudio

GET /api/sessions/:id/audio
Authorization: Bearer <token>
Accept: audio/wav (ou audio/x-raw)

Retorna stream binário de áudio capturado da aba do Chrome.

Limitações do áudio

  • Alta latência (300–600 ms) devido à captura e processamento.
  • Apenas áudio da aba ativa (Chrome headless).
  • Maior consumo CPU (~10-20% extra).
  • Formato bruto (PCM) ou WAV — precisa ser decodificado no cliente.
  • Não sincronizado com vídeo. Use a síncrona no cliente se necessário.

🔧 Troubleshooting de Streaming

❌ Imagem congelada (último frame para sempre)

  • Processo FFmpeg morreu? Verifique: ps aux | grep ffmpeg
  • Token expirou? Recrie a sessão.
  • Erro no Xvfb? Verifique se o display ainda existe: ps aux | grep Xvfb

❌ Qualidade muito ruim (pixels blocados)

  • Aumente quality (ex: 3 em vez de 7) — menor número = melhor qualidade.
  • Verifique se a largura/altura são muito baixas para o conteúdo.

❌ Latência alta (1s+)

  • Reduza resolução (ex: 800×600).
  • Reduza FPS (ex: 10).
  • Verifique rede (ping, jitter).

❌ Áudio não funciona

  • Verifique se audio: true foi passado na criação.
  • O Audio Manager Agent está carregado? Veja logs do servidor.
  • Chrome não suporta captura de áudio em headless puro — pode exigir patch ou usar PulseAudio虚拟.

💡 Boas Práticas

  • Use resolução mínima suficiente: Para formulários, 1024×768 ou 800×600 são ótimos.
  • FPS entre 10–15: É suficiente para controle manual, diminui CPU.
  • Qualidade 5–7: Boa relação tamanho/qualidade. Use 3 apenas se precisar de alta fidelidade.
  • Desabilite áudio se não for necessário — consome ~15% CPU extra.
  • Teste local primeiro: Valide configurações antes de ir para produção remota.
  • Monitore memória: sessões com alta resolução podem fugir do controle (memory leak no Chrome). Reinicie sessões after ~30 minutos se usar alta resolução.
