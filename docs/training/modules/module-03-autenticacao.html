Módulo 3: Autenticação e Gestão de Tenants

Entenda o sistema de autenticação JWT, criação e validação de chaves API, e isolamento por tenant.

Duração estimada25 minutos
DificuldadeBásico/Intermediário
Pré-requisitosServidor instalado (Módulo 2)

🎯 Objetivos deste módulo

  • Compreender o modelo de tenant isolation

    Cada cliente (tenant) tem seu próprio espaço de arquivos e chave API única.

  • Aprender a criar e gerenciar chaves API

    Fluxo completo: geração → armazenamento seguro → derivação de tenantId.

  • Entender o fluxo JWT

    Login, geração de token, verificação em cada requisição e renovação.

  • Integrar autenticação no frontend

    Exemplos práticos de login, uso do token e refresh.

🔐 Modelo de Segurança

Princípio fundamental: Cada requisição ao Serende deve incluir um JWT válido no header Authorization: Bearer <token>. O token contém o tenantId que determina o isolamento de arquivos e sessões.

Componentes

ComponenteResponsabilidade
key-store (SQLite)Armazena { keyHash, tenantId }. A chave é hasheada com SHA256, nunca armazenada em texto puro.
auth.jsFunções generateToken, verifyToken, deriveTenantId, e middleware authMiddleware.
JWT_SECRETSegredo HMAC usado para assinar tokens (HS256). Deve ser mantido em .env e ter alta entropia.
JWT_EXPIRYTempo de vida do token (padrão: 24h).

🔄 Fluxo de Autenticação Detalhado

1. Client
→
2. POST /api/auth/login
→
3. validateKey
→
4. generateToken
→
5. JWT

Passo a passo

  1. Cliente possui uma API Key (ex: sk_demo_abc123) obtida previamente do administrador.
  2. Envia POST /api/auth/login com JSON { "apiKey": "sk_demo_..." }.
  3. Backend calcula hash = SHA256(apiKey) e busca no SQLite via key-store.get(hash).
  4. Se encontrado, obtém tenantId. Caso contrário, retorna 401 Invalid API key.
  5. Gera JWT com payload { tenantId, iat, exp } usando jsonwebtoken.sign com JWT_SECRET.
  6. Retorna { token, tenantId } ao cliente.
  7. Nas requisições seguintes, o cliente inclui Authorization: Bearer <token>.
  8. Middleware de autenticação valida o token com jwt.verify. Se válido, anexa req.tenantId e prossegue.
Nota sobrederivação: O tenantId é derivado diretamente da chave. Isso permite que diferentes clientes tenham acesso a diferentes namespaces de arquivos. Não use a mesma chave para múltiplos tenants.

🔑 Criando Chaves API

O Serende inclui um script utilitário para criar chaves. Só administradores com acesso ao filesystem podem criá-las.

ScriptCLI

node dist/scripts/create-key.js --tenant <nome-tenant>

Exemplo

$ node dist/scripts/create-key.js --tenant acme-corp
🏷️  Tenant: acme-corp
🔑 API Key (salve em local seguro): sk_acme_8f3e2a1b...
🔒 Hash (armazenado no SQLite): a3f5c9...

Formato da chave

  • sk_ prefixo (significa "secret key")
  • <tenant>_ identificador do tenant
  • 16+ caracteres aleatórios hex/base64
  • Exemplo completo: sk_acme_8f3e2a1b9c4d5e6f
⚠️ Segurança: Trate chaves API como senhas. Nunca as comite em repositórios, não as envie por email sem criptografia, e armazene apenas em cofres de segredos (Vault, .env, variáveis de ambiente do deploy).

💻 Integração Frontend — Exemplo Prático

O frontend do Serende (React) inclui componentes de login. Veja como integrar em um app custom.

1. Tela de login

// LoginScreen.tsx (exemplo)
const [apiKey, setApiKey] = useState('');

const handleLogin = async () => {
  const res = await fetch('https://serende.example.com/api/auth/login', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ apiKey })
  });

  if (!res.ok) {
    alert('Chave API inválida');
    return;
  }

  const { token, tenantId } = await res.json();
  localStorage.setItem('serende_token', token);
  localStorage.setItem('serende_tenant', tenantId);
  window.location.href = '/dashboard';
};

2. Cliente HTTP com token automático

// auth-client.ts
const token = localStorage.getItem('serende_token');

export async function apiFetch(url, options = {}) {
  const res = await fetch(url, {
    ...options,
    headers: {
      ...options.headers,
      'Authorization': `Bearer ${token}`
    }
  });

  if (res.status === 401) {
    // token expirado ou inválido → redirect para login
    window.location.href = '/login';
    throw new Error('Unauthorized');
  }

  return res;
}

3. Uso em componentes

// Criar uma sessão
const createSession = async () => {
  const res = await apiFetch('/api/sessions', {
    method: 'POST',
    body: JSON.stringify({ url: 'https://example.com' })
  });
  const data = await res.json();
  return data.sessionId;
};

🔍 Debug e Verificação

Decodificar JWT (sem verificar assinatura)

# Instale jwt-cli: npm install -g jwt-cli
jwt decode <seu-token-aqui>

Você verá o tenantId no payload.

Verificar chave no SQLite

sqlite3 data/key-store.db "SELECT * FROM api_keys WHERE keyHash = '<SHA256 da chave>';"

Testar autenticação com curl

TOKEN=$(curl -s -X POST http://localhost:3333/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"apiKey":"sk_demo_..."}' | jq -r .token)

# Agora use o token:
curl -H "Authorization: Bearer $TOKEN" http://localhost:3333/api/sessions
