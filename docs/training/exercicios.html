Exercícios Práticos

Teste seus conhecimentos com cenários reais. Esses exercícios cobrem todo o sistema Serende, da instalação ao monitoramento.

Instalação e Health Check

Configure o Serende em um Ubuntu 22.04 (ou similar) e valide a saúde do serviço. Este exercício testa os módulos 1 e 2.
  1. Instale as dependências do sistema: Node.js 18+, Python 3, FFmpeg, Xvfb, Chrome/Chromium.
  2. Clone o repositório e rode npm ci --only=production.
  3. Configure o .env com JWT_SECRET, ADMIN_SECRET e PORT=3333.
  4. Execute o build: npm run build e inicie com PM2.
  5. Teste o health endpoint: curl http://localhost:3333/health
  6. Verifique se o processo serende está ativo no PM2.
  • Instalação concluída sem erros
  • Health check retornou {"status":"ok"}
  • Processo rodando com PM2 (sem log de erro)

Criação de Chave e Autenticação JWT

Gere uma chave API para um novo tenant, faça login e decodifique o token. Testa módulos 2 e 3.
  1. Crie uma chave para o tenant minha-empresa usando o script create-key.js.
  2. Armazene a chave em um local seguro (simule um cofre).
  3. Faça login via API: POST /api/auth/login com JSON {"apiKey":"sk_minha-empresa_..."}.
  4. Capture o JWT retornado.
  5. Decodifique o token (use ferramenta online ou jwt decode CLI) e confirme o tenantId no payload.
  • Chave criada e salva
  • Login retornou token 200 OK
  • Token decodificado contém tenantId correto
  • Token tem expiração em ~24h

Criação e Monitoramento de Sessão

Inicie uma sessão de browser remoto, observe os processos do sistema e encerre-a corretamente. Módulos 3 e 4.
  1. Use o token anterior para criar uma sessão: POST /api/sessions com {"url":"https://example.com"}.
  2. Anote o sessionId, display e cdpPort retornados.
  3. Execute ps aux | grep -E "(Xvfb|chrome|ffmpeg)" e identifique os processos da sessão.
  4. Acesse o stream MJPEG: abra no navegador http://localhost:3333/api/sessions/{sessionId}/stream com o header Authorization.
  5. Encerre a sessão com DELETE /api/sessions/{sessionId}.
  6. Verifique que os processos Xvfb/Chrome/FFmpeg desapareceram.
  • Sessão criada com sucesso (200 OK)
  • 3 processos ativos (Xvfb, Chrome, FFmpeg)
  • Stream MJPEG acessível no navegador
  • Sessão encerrada com sucesso
  • Processos mortos após DELETE

Input de Mouse e Teclado

Envie eventos de input para controlar a sessão remota. Requer sessão ativa do exercício anterior. Módulos 4 e 5.
  1. Com a sessão ativa e o stream carregado, envie um mousemove para coordenadas x=600, y=400.
  2. Envie um mousedown e mouseup para simular um clique no botão esquerdo (button=1).
  3. Envie uma sequência de keydown/keyup para digitar "Olá" (teclas: O, l, á).
  4. Use scroll para rolar a página.
  5. Observe a tela remota: o cursor deve se mover, clicar e digitar.

Exemplo curl para movermouse

TOKEN="<seu-token>"
SESSION="<session-id>"

curl -X POST http://localhost:3333/api/sessions/$SESSION/input \\
 -H "Authorization: Bearer $TOKEN" \\
 -H "Content-Type: application/json" \\
 -d '{"events":[{"type":"mousemove","x":600,"y":400}]}'
  • Mouse moveu para posição correta
  • Clique funcionou (botão pressionado e solto)
  • Teclas digitadas apareceram no campo correto
  • Scroll funcionou (página rolou)

Comandos CDP (Chrome DevTools Protocol)

Execute comandos CDP para interagir com o Chrome. Exemplos: capturar screenshot, obter título da página, navegar via CDP.
  1. Descubra o cdpPort da sua sessão (ex: 9223).
  2. Faça uma requisição POST /api/cdp/:port/Page.navigate com body {"url":"https://google.com"}.
  3. Capture um screenshot: POST /api/cdp/:port/Page.captureScreenshot (sem body).
  4. Obtenha o título da página: POST /api/cdp/:port/Runtime.evaluate com {"expression":"document.title"}.
  5. Salve o screenshot retornado (base64) em um arquivo screenshot.png.
# Exemplo: capturar screenshot
curl -X POST http://localhost:3333/api/cdp/9223/Page.captureScreenshot \\
 -H "Authorization: Bearer $TOKEN" \\
 -H "Content-Type: application/json" \\
 -d '{"format":"png"}' | jq -r .data | base64 -d > screenshot.png
  • Navegação via CDP funcionou (página mudou)
  • Screenshot salvo como PNG válido
  • Título da página obtido via Runtime.evaluate

Admin: Gerenciamento de Chaves

Use o painel admin ou API para criar, listar e revogar chaves. Testa módulos 7 e 8.
  1. Acesse o painel admin (frontend) ou use API com x-admin-secret.
  2. Crie uma nova chave para o tenant teste-tenant.
  3. Liste todas as chaves e confirme que a nova aparece.
  4. Revogue uma chave antiga (DELETE ou PATCH).
  5. Tente usar a chave revogada — deve retornar 401.
# Criar chave
curl -X POST http://localhost:3333/api/admin/keys \\
 -H "x-admin-secret: $ADMIN_SECRET" \\
 -H "Content-Type: application/json" \\
 -d '{"tenantId":"teste-tenant"}'
  • Nova chave criada com sucesso
  • Listagem retorna todas as chaves
  • Chave revogada (status não encontrado)
  • Chave revogada não funciona mais no login

Monitoramento de Sessões e Logs

Use PM2 e endpoints de admin para observar a saúde do sistema.
  1. Com 2-3 sessões ativas, execute pm2 logs serende --lines 50.
  2. Identifique logs de criação de sessão (nível info).
  3. Use GET /api/admin/sessions para listar sessões ativas.
  4. Use GET /api/admin/stats para obter estatísticas.
  5. Simule uma sessão com erro (envie input inválido) e observe log de erro.
  • Logs de criação de sessão vistos no PM2
  • Admin/sessions retornou JSON com sessões
  • Admin/stats retornou métricas (uptime, memória)
  • Erro apareceu nos logs com requestId
