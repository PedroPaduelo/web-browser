🏢 Sistema Multi-tenant

O que é Multi-tenant?

Permite que múltiplas organizações (tenants) usem a mesma instância do Serende com isolamento completo de dados e recursos.

Estrutura do Tenant

Tenant {
  id: UUID
  name: string
  apiKey: string (hash SHA-256)
  apiKeyPlain?: string (apenas criação)
  createdAt: datetime
  expiresAt?: datetime
  metadata?: JSON
  active: boolean
}

Isolamento

  • API Keys únicas por tenant
  • IDs de sessão prefixados com tenant ID
  • Xvfb displays separados por tenant (opcional)
  • Perfis isolados no filesystem
  • Limites de uso configuráveis por tenant
  • 🔄 Fluxo Completo

Origem da Detecção

O tenant é identificado por:

  1. API Key no Header x-api-key ou body de login
  2. Token JWT contém tenantId no payload

Tenant Manager

Módulo tenant-manager.js gerencia:

  • CRUD de tenants (criar, listar, editar, deletar)
  • Geração de API Keys (UUIDs)
  • Hash de API Keys (SHA-256)
  • Validação de expiração de API Keys
  • Contadores de uso por tenant
  • 🔄 Fluxo Completo

Endpoints de Tenant

Método Rota Autenticação Descrição
GET /api/tenants Admin Listar todos os tenants
POST /api/tenants Admin Criar novo tenant
GET /api/tenants/:id Admin Detalhes do tenant
DELETE /api/tenants/:id Admin Remover tenant
POST /api/tenants/:id/keys Admin Gerar nova API Key

Limitações por Tenant

Podem ser configuradas por tenant:

  • Max sessões simultâneas (ex: 5)
  • Timeout padrão para sessões (ex: 30 min)
  • Resolução máxima permitida (ex: 720p)
  • Rate limits de API específicos
  • Quota de storage para profiles
  • 🔄 Fluxo Completo

Pontos de Falha

  • 🔴 Feature creep: Muitos tenants consumindo recursos concorrentemente
  • 🟡 Proteção insuficiente: Tenants maliciosos podem tentar DoS
  • 🟡 Dados vazados: Bug de isolamento pode expor dados entre tenants
