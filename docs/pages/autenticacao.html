🔐 Sistema de Autenticação

Visão Geral

O sistema de autenticação do Serende utiliza API Keys combinadas com JWT (JSON Web Tokens) para prover acesso seguro e multi-tenant ao sistema.

Fluxo de Autenticação

┌─────────────┐     POST /api/auth/login      ┌─────────────┐
│   Cliente   │ ──────────────────────────→  │   Servidor  │
│  (Browser)  │                              │   Express   │
└─────────────┘                              └──────┬──────┘
     │                                                │
     │  { token, tenantId, expiresIn }               │
     ←───────────────────────────────────────────────┘
     │
     │  Authorization: Bearer {token}
     ▼
┌─────────────┐
│  Recursos   │
│  Protegidos │
└─────────────┘

API Key

Cada tenant possui uma API Key única que serve como credencial principal de acesso.

Características

  • Formato: UUID v4
  • Armazenamento: Hash SHA-256 no banco SQLite
  • Validade: Definida por tenant (pode expirar)
  • Rate Limit: 5 tentativas por minuto por IP
  • 🔄 Fluxo Completo

Endpoints de API Key

Método Rota Descrição
POST /api/auth/login Gera JWT a partir de API Key
POST /api/keys Cria nova API Key (admin)
GET /api/keys Lista todas as keys
DELETE /api/keys/:id Revoga API Key

JWT (JSON Web Token)

O JWT é gerado após login bem-sucedido e utilizado para autenticar todas as requisições subsequentes.

Payload do Token

{
  "sub": "tenant-id-uuid",
  "tenantId": "tenant-id-uuid",
  "iat": 1700000000,
  "exp": 1700086400
}

Configurações

  • Algoritmo: HS256
  • Validade: 24 horas
  • Secret: Configurado via variável de ambiente JWT_SECRET
  • 🔄 Fluxo Completo

Middleware de Autenticação

O servidor Express utiliza middleware para proteger rotas:

// Pseudo-código do middleware
function authMiddleware(req, res, next) {
  const token = req.headers.authorization?.replace('Bearer ', '')

  if (!token) {
    return res.status(401).json({ error: 'Token required' })
  }

  try {
    const decoded = jwt.verify(token, JWT_SECRET)
    req.tenantId = decoded.tenantId
    next()
  } catch (err) {
    return res.status(401).json({ error: 'Invalid token' })
  }
}

Rate Limiting

Proteção contra brute-force em endpoints de autenticação:

  • Limite: 5 tentativas por minuto
  • Identificação: IP do cliente
  • Módulo: @fastify/rate-limit
  • 🔄 Fluxo Completo

Fluxo de Dados

1 API Key Cliente envia API Key no body
→
2 Validação Server verifica hash no SQLite
→
3 JWT Gera token com tenantId
→
4 Response Retorna token + tenantId

Pontos de Falha

  • 🔴 JWT_SECRET exposto: Se a variável de ambiente vazar, atacantes podem gerar tokens válidos
  • 🟡 API Key sem rotação: Keys antigas não expiram automaticamente se não configurado
  • 🟡 Rate limit por IP: Pode ser burlado com IP rotativo
