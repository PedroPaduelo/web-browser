Sistema de Autenticação

O Serende usa API Key como credencial inicial, que é trocada por um JWT. O tenant ID é derivado do hash da API Key, garantindo isolamento entre clientes.

Fluxo de Login

Código de Autenticação

Login (auth.js)

const { generateToken, verifyToken } = require('./auth');

app.post('/api/auth/login', (req, res) => {
  const { apiKey } = req.body;
  const tenant = keyStore.validateKey(apiKey);
  if (!tenant) return res.status(401).json({ error: 'Invalid API key' });

  const token = generateToken(tenant.id, { maxSessions: tenant.maxSessions });
  res.json({ token, tenantId: tenant.id });
});

Middleware (auth.js)

function authMiddleware(req, res, next) {
  const token = req.headers.authorization?.slice(7);
  const payload = verifyToken(token);
  if (!payload) return res.status(401).json({ error: 'Token required' });

  req.tenant = {
    tenantId: payload.tenantId,
    maxSessions: payload.maxSessions
  };
  next();
}

Isolamento de Tenants

🔑

API Key

Cada tenant recebe uma API Key única. O tenant ID é derivado via SHA256 do hash da chave.

deriveTenantId(apiKey) =
  sha256(apiKey).slice(0,16)
📁

Profile Dir

Perfiles são armazenados em data/tenants/{tenantId}/. Isolamento físico no filesystem.

data/tenants/
  └── {tenantId}/
      ├── profiles/
      └── sessions/
🔒

Session Limit

Cada tenant pode ter limite custom de sessões simultâneas, definido no registro da API Key.

maxSessions: 5  // limite por tenant

Recursos de Segurança

Rate Limiting

  • • Global: 100 req/min em /api/**
  • • Login: 5 tentativas/min por IP
  • • Implementação via express-rate-limit

Helmet & CORS

  • • Helmet com CSP desabilitado (vídeo via canvas)
  • • CORS configurável via CORS_ORIGIN
  • • Credenciais habilitadas

Tenant Validation

  • • Verificação em todas as rotas protegidas
  • • session.tenantId === req.tenant.tenantId
  • • Bloqueio de cross-tenant access

SQLite KeyStore

  • • API Keys armazenadas em SQLite
  • • Suporte a migração legacy (AUTH_API_KEY)
  • • Enable/disable por tenant
