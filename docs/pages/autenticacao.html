Autenticacao e Autorizacao

Visao Geral

Sistema de autenticacao em 3 camadas independentes:

  • API Keys - Identificacao do tenant (quem e o cliente)
  • JWT - Sessao do usuario (token de acesso temporario)
  • Admin Secret - Operacoes administrativas (gerenciar keys e sistema)

Fluxo de Autenticacao

1
POST /api/auth/login
Cliente envia API Key no body do request
2
Validacao
SHA256 hash da key comparado com hash armazenado no SQLite
3
JWT Gerado
Token com tenantId e expiracao de 24h retornado ao cliente
4
Acesso
Bearer token incluido no header Authorization de todos os requests

API Keys

  • Formato: sk_ + 32 chars hex (64 caracteres total)
  • Armazenamento: SHA256 hash no SQLite (nunca plaintext)
  • TenantId: SHA256(apiKey).slice(0, 16) - 16 caracteres hexadecimais
  • Atributos por key: name, enabled, maxSessions, maxSessionDuration, maxIdleTimeout, features
  • Key prefix: primeiros 10 chars visiveis na UI (ex: sk_a1b2c3...)

JWT (JSON Web Token)

  • Algoritmo: HS256
  • Secret: JWT_SECRET (variavel de ambiente, 128 chars)
  • Expiracao: 24h (configuravel via JWT_EXPIRY)
  • Verificacao: authMiddleware em todas as rotas /api/* (exceto login e health)
// Payload do JWT
{
  "tenantId": "a1b2c3d4e5f67890",
  "maxSessions": 5,
  "iat": 1700000000,
  "exp": 1700086400
}

// Header HTTP
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

Rate Limiting

  • Login: 5 tentativas por IP por 60 segundos (in-memory Map)
  • Global API: 100 requests por IP por 60 segundos (express-rate-limit)
  • Resposta: HTTP 429 Too Many Requests com header Retry-After

Admin Routes

Todas as rotas administrativas requerem o header x-admin-secret (comparacao timing-safe).

Metodo Rota Descricao
POST/api/admin/keysCriar nova API key
GET/api/admin/keysListar todas as keys
PATCH/api/admin/keys/:idAtualizar key
POST/api/admin/keys/:id/regenerateRegenerar raw key
DELETE/api/admin/keys/:idRevogar key
GET/api/admin/sessionsListar sessoes ativas
GET/api/admin/statsEstatisticas do sistema

Fluxo no Frontend

  • Login: Usuario insere API key, POST /api/auth/login e executado, token salvo no localStorage (serende_token, serende_tenantId)
  • authFetch(): Wrapper do fetch que adiciona Bearer token automaticamente a todos os requests
  • isAuthenticated(): Verifica se token existe e nao expirou (decodifica campo exp do JWT)
  • Logout: Limpa localStorage e redireciona para tela de login
