🛡️ Seguranca

Camadas de Seguranca

O Serende implementa 6 camadas de seguranca independentes que atuam em sequencia para proteger cada request.

Helmet

Headers de seguranca automaticos: X-Frame-Options, X-Content-Type-Options, Referrer-Policy, HSTS. CSP esta desabilitado intencionalmente pois o streaming de JPEG via WebSocket requer politicas relaxadas de content loading.

Rate Limiting

Limite global de 100 requests/min por IP. Login restrito a 5 tentativas/min por IP. Implementado com express-rate-limit usando store in-memory. Suficiente para single-instance.

JWT

Algoritmo HS256 com secret de 128 caracteres. Expiracao fixa de 24 horas. Token verificado em cada request autenticado. Payload contem tenantId para isolamento.

API Keys

Armazenadas como SHA256 hash no SQLite. Prefixo sk_ para identificacao visual. Valor plaintext nunca persiste no banco -- so retornado uma vez na criacao.

CORS

Whitelist de origins configuravel via variavel de ambiente. Credentials habilitadas para permitir cookies e headers de autorizacao cross-origin.

Trust Proxy

app.set('trust proxy', 1) habilitado para funcionar atras do reverse proxy do EasyPanel. Garante que o IP real do cliente seja usado no rate limiting.

Fluxo de Seguranca por Request

Cada request HTTP passa por 5 camadas de verificacao antes de atingir o handler da rota.

1
Helmet
Request chega. Helmet adiciona headers de seguranca na resposta automaticamente.
2
CORS
Verifica origin do request contra whitelist configurada. Rejeita origens nao autorizadas.
3
Rate Limiter
Verifica limites por IP. 100/min global, 5/min para login. Retorna 429 se excedido.
4
Auth Middleware
Valida token JWT do header Authorization. Extrai tenantId do payload. Rejeita tokens expirados.
5
Ownership
Verifica se o recurso acessado pertence ao tenant autenticado. Impede cross-tenant access.

Admin Secret

Rotas administrativas (/api/admin/*) sao protegidas por um secret separado do JWT, transmitido via header HTTP.

  • Header: x-admin-secret
  • Comparacao: Utiliza crypto.timingSafeEqual() para prevenir timing attacks. A comparacao leva tempo constante independente de quantos bytes sao iguais.
  • Secret: Configurado via variavel de ambiente ADMIN_SECRET (64 caracteres hexadecimais recomendados)
  • Escopo: CRUD de API keys, listagem de todas as sessoes, estatisticas do sistema

WebSocket Security

A autenticacao WebSocket requer cuidados especiais pois headers customizados nao sao suportados no handshake do browser.

  • Token via query param: JWT passado na URL de conexao (/ws/stream?token=JWT&sessionId=ID)
  • Ownership no upgrade: Servidor verifica que session.userId === token.tenantId antes de aceitar o upgrade HTTP
  • Token checker periodico: A cada 60 segundos, o servidor itera sobre todas as conexoes ativas e desconecta aquelas cujo token expirou (close code 4001)
  • Separacao binario/JSON: Stream de video envia dados binarios (JPEG frames), input relay usa JSON. O servidor diferencia pelo tipo da mensagem WebSocket.

Dado Armazenamento Protecao
API Keys SHA256 hash no SQLite Nunca plaintext no banco
JWT Secret .env file 128 caracteres aleatorios
Admin Secret .env file 64 caracteres hex
Passwords N/A (usa API keys) N/A
Tokens JWT Client localStorage 24h expiry

Headers de Seguranca

Headers adicionados automaticamente pelo Helmet em cada resposta HTTP:

X-Content-Type-Options: nosniff
X-Frame-Options: SAMEORIGIN
X-XSS-Protection: 0
Referrer-Policy: no-referrer
Strict-Transport-Security: max-age=15552000
X-Request-Id: abc123 (rastreamento)

Nota: O header X-XSS-Protection: 0 segue a recomendacao moderna de desabilitar o filtro XSS do browser, que pode introduzir vulnerabilidades. O X-Request-Id e gerado por request para rastreamento em logs.
