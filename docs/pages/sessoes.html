💻 Gerenciamento de Sessões

O que é uma Sessão?

Uma sessão representa uma instância isolada de navegador rodando remotamente. Cada sessão inclui:

  • Display virtual (Xvfb)
  • Processo Chrome headless
  • Stream de vídeo (ffmpeg)
  • Processo de input (python-xlib)
  • Perfil de usuário (opcional)
  • 🔄 Fluxo Completo

Ciclo de Vida da Sessão

┌─────────────┐         POST /api/sessions         ┌─────────────┐
│   Cliente   │ ───────────────────────────────→ │   Servidor  │
│             │                                  │             │
└─────────────┘                                  └─────┬───────┘
                                                     │
                                                     │ 1. Valida request
                                                     │ 2. Spawn Xvfb
                                                     │ 3. Spawn Chrome
                                                     │ 4. Spawn FFmpeg
                                                     │ 5. Spawn Python Input
                                                     ▼
                                            ┌────────────────┐
                                            │ Sessão Ativa   │
                                            │ { sessionId }  │
                                            └────────┬───────┘
                                                     │
                                     WebSocket     │ HTTP
                                     (input+video) │ (status)
                                         │         │
                                         ▼         ▼
┌─────────────┐                  ┌─────────────────────┐
│   Browser   │ ←←←←←←←←←←←←←← │  Stream Manager     │
│   Viewer    │       MJPEG      │  & Input Handler    │
└─────────────┘                  └─────────────────────┘

Configurações da Sessão

Parâmetro Descrição Padrão Exemplo
resolution Resolução do display virtual 1280x720 1920x1080
startUrl URL inicial do Chrome https://google.com https://exemplo.com
timeout Tempo de auto-destruição (ms) 1800000 (30 min) 3600000

Request Body (POST /api/sessions)

{
  "resolution": "1920x1080",
  "startUrl": "https://example.com",
  "timeoutMs": 1800000,
  "copyProfile": true  // se houver profile salvo
}

Response Body

{
  "sessionId": "abc123def456",
  "playwrightWsUrl": "ws://localhost:3001/ws?sessionId=abc123...",
  "timeout": {
    "expiresAt": 1700000000000,
    "remaining": 1800000
  },
  "status": "active"
}

Status da Sessão

Status Descrição
creating Processos estão sendo spawnados
active Sessão funcionando normalmente
destroying Processos estão sendo encerrados
error Erro ao criar ou manter a sessão
idle Nenhuma sessão ativa

Session Manager

O session-manager.js é responsável por controlar o ciclo de vida das sessões:

  • Spawn de Xvfb com display virtual
  • Spawn de Chrome com CDP ativado
  • Spawn de FFmpeg para captura via x11grab
  • Spawn do daemon Python para input
  • Timeout e auto-destruição
  • Cleanup de processos filhos
  • Gerenciamento de perfil (master-session)
  • 🔄 Fluxo Completo

Perfis de Usuário (Profiles)

  • Master Session: Sessão dedicada que acumula cookies, logins, histórico
  • Clone: Novas sessões podem copiar profile da master
  • Isolamento: Cada sessão mantém seu próprio Xvfb independente
  • Persistence: Dados do profile armazenados em SQLite
  • 🔄 Fluxo Completo

Endpoints de Sessão

Método Rota Autenticação Descrição
POST /api/sessions Sim Criar nova sessão
GET /api/sessions Sim Listar sessões ativas
GET /api/sessions/:id Sim Obter info da sessão
POST /api/sessions/:id/close Sim Encerrar sessão

Limitações

  • 🔴 Memória: Cada Xvfb + Chrome consome ~300-500MB RAM
  • 🔴 CPU: FFmpeg encoding em tempo real usa CPU intensivamente
  • 🟡 Concorrência: Limitada pela capacidade do servidor
  • 🟡 Portas: Cada Chrome usa uma porta de debug aleatória
  • 🔄 Fluxo Completo

Configuração via CDP

O Chrome é iniciado com Chrome DevTools Protocol ativado para controle avançado:

{
  "args": [
    "--headless=new",
    "--no-sandbox",
    "--disable-setuid-sandbox",
    "--disable-dev-shm-usage",
    "--disable-software-rasterizer",
    "--remote-debugging-port=9222",
    "--window-size=1920,1080"
  ]
}
