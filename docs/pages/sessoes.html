Gerenciamento de Sessoes

Visao Geral

Cada sessao e uma instancia isolada de Chrome rodando em um display virtual Xvfb, com streaming de video via FFmpeg e input via Python X11. O limite maximo e de 10 sessoes simultaneas (configuravel via MAX_SESSIONS).

Ciclo de Vida

1
POST /api/session
Validacao de limites globais e por tenant (maxSessions da API key)
2
Alocacao
Display :100-:199 e CDP port 9222+ sao alocados (primeiro disponivel)
3
Spawn Xvfb
Display virtual X11 criado com a resolucao solicitada
4
Spawn Chrome
Chrome headless com --remote-debugging-port e --user-data-dir
5
Spawn FFmpeg
Captura x11grab do display, codifica MJPEG e envia para stdout
6
Ativo
StreamManager + InputHandler + Timeout tracker monitorando a sessao

Criacao de Sessao

POST /api/session
Authorization: Bearer {token}

{
  "resolution": "1280x720",
  "startUrl": "https://www.google.com",
  "extensionPath": null
}

Response 201:
{
  "sessionId": "uuid-v4",
  "status": "active",
  "resolution": "1280x720"
}

Timeout de Inatividade

  • Default: 30 minutos (configuravel via SESSION_TIMEOUT_MINUTES)
  • Verificacao: A cada 60 segundos por interval
  • Atividade atualizada em: HTTP requests, WebSocket messages, input events
  • Warning: Notificacao 2 minutos antes do timeout
  • Acao no timeout: Salva profile, destroi sessao e libera recursos
  • Timer na UI: Exibido no formato MM:SS no frontend

Encerramento

Ao encerrar uma sessao (DELETE /api/session/:sessionId), o sistema executa os seguintes passos em ordem:

  1. Salva profile do Chrome (merge com master)
  2. Mata processos: Chrome, FFmpeg, Xvfb, Python
  3. Libera display e CDP port
  4. Remove do Map de recursos
  5. Limpa pool CDP
