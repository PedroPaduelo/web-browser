⚠️ Riscos e Vulnerabilidades

Matriz de Riscos

Critico

  • !
    Acesso ao sistema de arquivos do servidor Chrome rodando no mesmo container pode acessar arquivos locais via file://. Mitigacao: Chrome sandbox habilitado, flag --no-remote, extensoes desabilitadas via --disable-extensions.
  • !
    Vazamento de memoria em sessoes longas FFmpeg + Chrome acumulam memoria ao longo do tempo sem liberacao adequada. Mitigacao: timeout de inatividade de 30 minutos forca destruicao da sessao e cleanup de todos os processos.

Alto

  • !
    DDoS no WebSocket Multiplas conexoes WebSocket simultaneas de um mesmo IP podem sobrecarregar o servidor. Mitigacao: rate limiting no upgrade + limite maximo de conexoes por tenant.
  • !
    Chrome exploit Vulnerabilidade zero-day no Chrome pode comprometer o servidor inteiro, ja que Chrome roda no mesmo container. Mitigacao: manter Chrome sempre atualizado, sandbox habilitado.
  • !
    Profile cross-contamination Bug no merge de profiles pode misturar dados de navegacao entre tenants diferentes. Mitigacao: tenantId como chave de diretorio (/data/tenants/{tenantId}/), validacao de ownership em cada operacao.

Medio

  • !
    JWT em localStorage Tokens armazenados no localStorage sao vulneraveis a ataques XSS. Mitigacao atual: expiracao de 24h. Futuro: migrar para HttpOnly cookies.
  • !
    SQLite single-writer WAL mode melhora leitura concorrente, mas escritas sao serializadas. Pode haver contencao sob carga. Mitigacao: operacoes de escrita sao raras (login, admin) -- a maioria dos requests e read-only.
  • !
    Sem HTTPS forcado internamente O servidor Node.js nao termina TLS -- confia no reverse proxy (EasyPanel) para HTTPS. Mitigacao: trust proxy habilitado + header HSTS com max-age de 180 dias.

Baixo

  • !
    Rate limiter in-memory Contadores de rate limiting sao perdidos ao reiniciar o processo. Mitigacao: baixo impacto na pratica, contadores resetam naturalmente apos a janela de tempo.
  • !
    Sessoes orfas Se o servidor crashar, processos Xvfb/Chrome/FFmpeg podem ficar rodando sem controle. Mitigacao: callback onSessionDied + rotina de cleanup no startup que mata processos orfaos.

Mitigacoes Implementadas

Risco Mitigacao Status
Brute force login Rate limiter 5/min/IP Implementado
Token expirado em WS Checker 60s + close code 4001 Implementado
Headers de seguranca Helmet completo (exceto CSP) Implementado
CORS aberto Whitelist configuravel via env Implementado
Admin sem protecao timing-safe comparison do secret Implementado
Session hijacking JWT + ownership validation por tenant Implementado
Memory leak Timeout 30min + cleanup de processos Implementado

Recomendacoes Futuras

  • CSP estrito: Implementar Content-Security-Policy restritivo. Atualmente desabilitado porque o streaming de JPEG via WebSocket requer politicas relaxadas.
  • HttpOnly cookies: Migrar JWT de localStorage para cookies HttpOnly para eliminar vetor de ataque XSS.
  • Seccomp sandbox: Adicionar perfil seccomp mais restritivo no Chrome para limitar syscalls disponiveis.
  • Audit log: Implementar log de auditoria para operacoes administrativas (criacao/revogacao de keys, listagem de sessoes).
  • Rate limiting distribuido: Migrar de in-memory para Redis para suportar multiplas instancias do servidor.
  • Backup automatizado: Configurar cron job para backup periodico do SQLite usando o comando .backup.
