Introdução

O que é o MCP Remote Browser e como ele funciona

🌐
Serende — Remote Browser Automation
MCP Server para controle de Chrome via IA
O MCP Remote Browser (Serende) é um servidor MCP que permite agentes de IA controlarem um navegador Chrome real de forma remota. Diferente de scraping tradicional, a IA pode ver a tela, clicar em elementos, digitar texto, e interagir como um humano faria.
🏗️
Arquitetura
AI → MCP → Chrome (CDP) → Xvfb
AI Agent (Claude)
    ↓ HTTP + X-API-Key
MCP Server (porta 4202)
    ↓ HTTP + JWT Bearer
Serende Backend (porta 4201)
    ↓ Chrome DevTools Protocol
Chrome Headless + Xvfb (display virtual)
📊
49 Tools em 15 Categorias
Sessão, Navegação, Screenshot, Mouse, Teclado, JS, Inspeção, Waiting, etc.
Cada tool exposta via MCP pode ser chamada pela IA para realizar uma ação específica no navegador. A IA decide sequencialmente qual tool usar baseado no contexto e objetivo da tarefa.

Setup Inicial

O MCP Serende é um servidor HTTP — basta configurar a URL e API key

🖥️
Claude Desktop
claude_desktop_config.json
Abra as configurações do Claude Desktop e adicione o MCP como HTTP: 
{
  "mcpServers": {
    "remote-browser": {
      "type": "http",
      "url": "https://SEU-DOMINIO.com:4202/mcp",
      "headers": {
        "X-API-Key": "4063020"
      }
    }
  }
}

Importante: O tipo é "http", não "stdio". O Serende roda como servidor HTTP independente — múltiplos clientes podem conectar simultaneamente.

⌨️
Claude Code (CLI)
.mcp.json na raiz do projeto
Crie um arquivo .mcp.json na raiz do seu projeto: 
{
  "mcpServers": {
    "remote-browser": {
      "type": "http",
      "url": "https://SEU-DOMINIO.com:4202/mcp",
      "headers": {
        "X-API-Key": "4063020"
      }
    }
  }
}

Reinicie o Claude Code após adicionar o arquivo. As 49 tools aparecerão automaticamente.

🔑
Autenticação
API Key via header X-API-Key
A autenticação é feita automaticamente pelo cliente MCP via header X-API-Key.

Internamente, o MCP server:

  • Recebe a API key no header
  • Autentica com o backend Serende (POST /api/auth/login)
  • Recebe um JWT token (24h de validade)
  • Deriva um tenantId único via SHA256 para isolamento
  • Usa o JWT em todas as chamadas subsequentes

Cada API key gera um tenant isolado — sessões, profiles e dados não vazam entre clientes.

Ciclo de Vida de uma Sessão

Fluxo obrigatório que toda IA deve seguir

01
USER REQUEST — Usuário solicita tarefa que requer navegador
↓
02
AI DECIDE PRECISA DO BROWSER — Analisa se a tarefa envolve web/HTML/interação
↓
03
session_start() — Cria sessão Xvfb + Chrome, retorna sessionId e viewerUrl
↓
04
screenshot() — Captura tela atual para IA ver onde está
↓
05
IDENTIFY ACTION — IA decide próxima ação (navigate, click, type, etc)
↓
06
EXECUTE TOOL — Chama tool apropriada (navigate, click_element, type_text...)
↓
07
WAIT/VALIDATE — Confirma que ação funcionou (wait_for_element, screenshot)
↓
08
REPEAT — Volta para passo 4 até completar tarefa
↓
09
session_stop() — Libera recursos (Xvfb, Chrome, profile)

Guia de Decisão da IA

Qual tool usar em cada situação

PRECISA INTERAGIR COM PÁGINA WEB?
NÃO → Use outras ferramentas
PRIMEIRA VEZ NESTA SESSÃO?
SIM → session_start()
JÁ TEM SESSÃO ATIVA?
NÃO → session_start()
SIM → Continua...
PRECISA IR PARA OUTRA PÁGINA?
SIM → navigate(url)
NÃO → Continua...
PRECISA VER O QUE TEM NA TELA?
QUER TEXTO? → get_page_text() / get_page_title()
QUER IMAGEM? → screenshot()
QUER HTML/DOM? → get_page_html() / find_element()
QUER ELEMENTO ESPECÍFICO? → find_element() / find_element_by_text()
PRECISA CLICAR EM ALGO?
CONHECE SELECTOR? → click_element(selector)
CONHECE TEXTO VISÍVEL? → click_by_text(text)
CONHECE COORDENADAS? → mouse_click(x, y)
NÃO SABE ONDE É → screenshot() + find_element()
PRECISA DIGITAR/PREENCHER?
ÚNICO CAMPO → click_element() + type_text() ou click_and_type()
MÚLTIPLOS CAMPOS → fill_form([{selector, value}...])
INPUT REACT → react_fill_input() (Formik, RHF, controlled)
PRECISA ESPERAR ALGO?
ELEMENTO APARECER → wait_for_element(selector)
ELEMENTO SUMIR → wait_for_selector_gone(selector)
PÁGINA CARREGAR → wait_for_page_ready()
URL MUDAR → wait_for_url(pattern)
TEXTO APARECER → wait_for_text(text)
TERMINOU TAREFA?
SIM → session_stop()
NÃO → Volta para "PRECISA VER O QUE TEM NA TELA?"

Boas Práticas para IA

Maximize eficácia e minimize erros

📸

SEMPRE comece com screenshot

Antes de clicar/interagir, veja onde está. Um screenshot evita cliques errados e dá contexto.

⏱️

Use wait_for_page_ready() após navegação

Garanta que a página carregou completamente antes de interagir (readyState + network idle).

🎯

Prefira high-level tools

Use click_element() ao invés de mouse_click() com coordenadas. Mais robusto.

⚛️

Lidere com React inputs

Para inputs modernos (Formik, RHF, controlled), use react_fill_input() ao invés de type_text().

🛑

Sempre pare a sessão

session_stop() libera recursos (Xvfb, Chrome, profile). Não esqueça!

🔍

Use find_element_by_text() quando não tem selector

Busca por texto visível é mais flexível que selectors frágeis.

⏰

Trate timeouts

Defina timeoutMs apropriado. Default 30s pode ser muito.

🔗

Combine screenshot + get_page_text()

Análise completa do estado: visual (screenshot) + texto (get_page_text).

Troubleshooting

Problemas comuns e soluções

Problema Solução
"No active session" Chame session_start() primeiro antes de qualquer outra tool
Elemento não aparece Use wait_for_element() com timeout maior ou verifique selector
Click não funciona Tente scroll_to_element() antes para garantir que está visível
Input React não preenche Use react_fill_input() ao invés de type_text()
Página não carrega Use wait_for_page_ready() com checkNetwork=true
Selector muda dinamicamente Use find_element_by_text() ou data-testid
Click errado (múltiplos elementos) Use selector mais específico ou find_all_elements() + índice
Drag não funciona Verifique se está usando drag() com coordenadas corretas (fromX/Y → toX/Y)
